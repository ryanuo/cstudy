## 遇到的文件，以及如何解决的

### 问题1：任务文件读取格式错误

在 C 语言中，`fscanf` 除了常见的 `%d`、`%s` 等格式符外，还支持 **Scanset（扫描集）** 语法，例如 `%[^,]`。其中 `^` 表示“取反”，`%[^,]` 的含义是：**读取所有不是逗号的字符，直到遇到逗号为止**。这种写法非常适合解析 CSV 文件或逗号分隔的数据。

例如，对于数据：

```text
TASK001,学习C语言,1
```

使用：

```c
fscanf(fp, "%31[^,],%63[^,],%d",
       id,
       name,
       &priority);
```

可以分别读取出任务 ID、任务名称和优先级。

需要注意的是，`%s` 和 `%[^,]` 的行为有明显区别。`%s` 会自动跳过前导空白字符，并在遇到空格、换行或 Tab 时停止读取；而 `%[^,]` 不会自动跳过前导空白，它只关心是否遇到逗号。因此，如果文件中存在换行符残留，可能会把 `\n` 一起读入字符串。为了避免这个问题，工程实践中通常会这样写：

```c
" %31[^,]"
```

格式串前面的空格会自动跳过所有空白字符，包括空格、换行符和制表符，从而提高程序的健壮性。

另外，在使用 `%[^,]` 时一定要加长度限制，例如 `%31[^,]`，否则当输入数据超过缓冲区大小时，可能导致缓冲区溢出，引发严重的安全问题。

因此，在实际项目开发中，`%[^,]` 是解析结构化文本数据的常用技巧，而“长度限制 + 前导空格”则是保证代码安全和稳定的重要实践。

### 问题2: 任务撤销后位置错误

在实现任务撤销（Undo）功能时，最初仅保存了被删除任务的数据。
当执行撤销操作时，任务会重新插入链表，但只能追加到链表尾部，导致任务顺序发生变化，无法恢复到删除前的状态。

在删除任务时，除了保存任务数据外，还额外保存：
删除任务的数据
前驱节点 ID（Prev Task ID）
撤销时根据前驱节点重新定位，并插入到原来的位置。

```c
typedef struct stack_node
{
    operation_type_t op_type; // 操作类型
    task_data_t task_data;    // 保存的任务数据
    char prev_task_id[32];
    struct stack_node *next;
} stack_node_t;
```
