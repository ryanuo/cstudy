# 线程池（ThreadPool）流程笔记

## 一、线程池核心参数

| 参数 | 说明 |
|------|------|
| `corePoolSize` | 核心线程数，即使空闲也不会被回收（除非开启 `allowCoreThreadTimeOut`） |
| `maximumPoolSize` | 最大线程数 = 核心线程 + 非核心线程 |
| `keepAliveTime` | 非核心线程的空闲存活时间 |
| `workQueue` | 任务等待队列（阻塞队列） |
| `threadFactory` | 线程工厂，用于创建新线程 |
| `handler` | 拒绝策略，当队列满且线程数达到上限时触发 |

## 二、任务提交流程（核心流程）

```
提交任务 (execute)
       │
       ▼
┌─────────────────────┐
│ 当前线程数 < coreSize? │──Yes──▶ 创建核心线程执行任务
└─────────────────────┘
       │ No
       ▼
┌─────────────────────┐
│ 工作队列是否未满？      │──Yes──▶ 任务入队等待
└─────────────────────┘
       │ No
       ▼
┌─────────────────────────┐
│ 当前线程数 < maximumSize? │──Yes──▶ 创建非核心线程执行任务
└─────────────────────────┘
       │ No
       ▼
┌─────────────────────┐
│   触发拒绝策略（Reject）  │
└─────────────────────┘
```

### 关键规则

1. **优先创建核心线程**：线程数未达到 `corePoolSize` 时，即使有空闲线程，也会创建新线程
2. **其次入队**：核心线程已满时，任务进入等待队列
3. **最后扩容**：队列满了才创建非核心线程（`corePoolSize` → `maximumPoolSize`）
4. **最终拒绝**：队列满 + 线程数达到上限 → 执行拒绝策略

> ⚠️ 这个顺序是面试高频考点：**先核心线程 → 再队列 → 再非核心线程 → 最后拒绝**

## 三、线程池生命周期（状态转换）

```
        ┌──────────┐
        │  RUNNING  │ ← 初始状态，接收新任务 + 处理队列任务
        └────┬─────┘
             │ shutdown()
             ▼
        ┌──────────┐
        │ SHUTDOWN  │ ← 不接收新任务，但处理队列中已有任务
        └────┬─────┘
             │ shutdownNow()
             ▼
        ┌──────────┐
        │   STOP    │ ← 不接收新任务，中断正在执行的任务，清空队列
        └────┬─────┘
             │
             ▼
        ┌──────────┐
        │ TIDYING   │ ← 所有任务已终止，workerCount = 0
        └────┬─────┘
             │ terminated() 钩子执行完毕
             ▼
        ┌──────────┐
        │TERMINATED │ ← 线程池彻底终止
        └──────────┘
```

| 状态 | 接收新任务 | 处理队列任务 | 中断执行中任务 |
|------|:---------:|:----------:|:------------:|
| RUNNING | ✅ | ✅ | ❌ |
| SHUTDOWN | ❌ | ✅ | ❌ |
| STOP | ❌ | ❌ | ✅ |
| TIDYING | ❌ | ❌ | ❌ |
| TERMINATED | ❌ | ❌ | ❌ |

## 四、Worker 线程执行流程

```
Worker.run()
    │
    ▼
┌────────────────────┐
│ 执行 firstTask      │ ← 首次任务（创建时传入）
└────────┬───────────┘
         │
         ▼
┌────────────────────────┐
│ getTask() 循环获取任务   │◀──────────────────┐
└────────┬───────────────┘                    │
         │                                    │
    ┌────┴────┐                               │
    │ 有任务？  │──No──▶ 线程退出（回收）       │
    └────┬────┘                               │
         │ Yes                                │
         ▼                                    │
┌────────────────────┐                        │
│   执行 task.run()   │────────────────────────┘
└────────────────────┘
```

### getTask() 获取任务的逻辑

- 从 `workQueue.poll(keepAliveTime)` 获取（非核心线程超时等待）
- 从 `workQueue.take()` 获取（核心线程无限等待）
- 返回 `null` 时，Worker 退出循环并被回收

## 五、拒绝策略

| 策略 | 行为 |
|------|------|
| `AbortPolicy`（默认） | 抛出 `RejectedExecutionException` |
| `CallerRunsPolicy` | 由提交任务的线程自己执行 |
| `DiscardPolicy` | 静默丢弃 |
| `DiscardOldestPolicy` | 丢弃队列最前面的任务，然后重试提交 |

## 六、常用线程池对比

| 线程池类型 | coreSize | maxSize | 队列 | 适用场景 |
|-----------|---------|---------|------|---------|
| `FixedThreadPool` | n | n | 无界队列 | 负载稳定 |
| `CachedThreadPool` | 0 | Integer.MAX_VALUE | 同步队列（容量0） | 大量短任务 |
| `SingleThreadExecutor` | 1 | 1 | 无界队列 | 顺序执行 |
| `ScheduledThreadPool` | n | Integer.MAX_VALUE | 延迟队列 | 定时/周期任务 |

## 七、线程数配置建议

| 场景 | 推荐公式 |
|------|---------|
| **CPU 密集型** | `N_cpu + 1` |
| **IO 密集型** | `N_cpu × (1 + 平均等待时间/计算时间)` |
| **混合型** | 拆分为两个线程池分别处理 |

## 八、常见问题

### Q1: 核心线程和非核心线程有本质区别吗？
**没有。** 线程池不区分"核心"和"非核心"线程，只是通过当前线程数与 `corePoolSize` 的比较来决定回收策略。所有 Worker 都是平等的。

### Q2: 为什么 `FixedPoolSize` 用无界队列？
因为 `coreSize == maxSize`，永远不会创建非核心线程，所以不需要有界队列来触发扩容。

### Q3: 任务入队后什么时候被执行？
当核心线程空闲时，通过 `getTask()` 从队列中取出执行。如果核心线程都在忙，任务会一直等待直到有线程空闲。

### Q4: `shutdown()` vs `shutdownNow()`？
- `shutdown()`：温和关闭，等队列中任务执行完
- `shutdownNow()`：强制关闭，中断所有线程，返回未执行的任务列表
